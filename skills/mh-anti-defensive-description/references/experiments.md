# 让实验识别与发展真正的贡献

在实验设计、对照与消融选择、结果解释、实验调整及研究推进时使用。围绕当前任务交付可执行设计；不因自动启用本 skill 就擅自启动训练或扩大研究范围。

## 从贡献推导实验

把贡献写成可检验命题，例如：“在存在指定困难、且信息与计算权限相同的条件下，新机制通过某个过程改善某项能力。”据此确定主要终点、最强替代解释和能区分它们的对照。

性能提升、机制理解、效率、鲁棒性、可适用条件扩展可以是不同研究目标。选择与科学问题相符的指标，不要求所有维度同时领先，也不在看到结果后随意改换主目标。

按需要使用紧凑矩阵：

| 待检验主张 | 关键比较或干预 | 测量与判定 |
|---|---|---|
| 新方法有实际价值 | 与目标相同、能力充分的强基线比较 | 预定主要指标、实际意义及不确定性 |
| 收益来自新增机制 | 关闭、替换或干预该机制，其余条件保持合理可比 | 过程变量、结果变化、替代解释 |
| 收益来自机制耦合 | 完整方法与独立组合、固定策略或简单同信息策略比较 | 是否存在预期相互作用 |
| 改善有明确适用条件 | 对关键难度或物理量作有根据的变化 | 条件收益、边界、失败情形 |
| 代价与收益有意义 | 等预算或完整报告计算、数据、控制及调参资源 | 公平条件下的权衡 |

只设计回答核心问题所需的实验。增加很多图和模块不能替代有辨别力的对照。

## 公平且有辨别力的对照

- 选择最相关已有方法和有竞争力的简单方案；常规基线已能充分解决的问题，需要重新识别新增价值。
- 尽可能统一观测信息、数据划分、控制权限、约束、训练与调参预算、终止规则和评价条件。无法统一的差异要说明，避免将额外资源的收益归给机制。
- 消融应对应声称机制。若移除模块破坏整个接口，增加合理替代版本，避免只证明完整系统能运行。
- 预期收益发生的条件应从机制提出。兼顾关键对照条件和合理失败边界，避免只选方法容易获胜的场景。
- 报告与主要结论相关的失败、停止、删失和成本；不能丢弃不利运行后再汇总“成功样本”。

## 探索与确认

早期探索用于检查实现、理解机制、找适用条件和估计波动。根据问题规模确定运行次数；固定少量种子既不自动证明有效，也不自动证明无效。

用探索结果修改方法或提出条件性假设后，记录修改依据，再冻结主要比较、终点、样本选择、停止规则和分析方法，使用未参与选择的数据、种子或场景进行确认。事后发现可作为新线索，不能写成预先预测并确认的结论。

涉及随机性时，采用适合问题的重复、配对、效应量和不确定性分析。实验预算由预期波动、效应与资源决定，不机械指定一个适用于所有问题的样本数。新训练仍遵循用户的运行环境、硬件和复现要求。

## 初期结果不理想时怎样继续

先确定失败对应哪一层，不把所有问题归为“方向没有创新”：

1. **实现与可比性**：符号、尺度、接口、终止条件、优化收敛、预算与信息权限是否正确？用有针对性的检查排除具体故障，不假设一定有 bug。
2. **机制是否发生**：目标困难是否出现？新增模块是否实际介入？过程变量是否符合预期？
3. **证据是否足够**：效应是否被高方差、少量运行或不合适测量掩盖？同时考虑可能确实没有有意义收益。
4. **哪一主张被反驳**：总体性能、特定条件收益、机制解释和理论主张分别判断，避免相互偷换。

据此选择最能增加信息的一项后续实验，而非盲目扩大训练或添加模块。若新方法总体落后但某条件可能有价值，将其作为待确认的条件性假设，保留原始总体比较和强基线。若确认实验不支持核心机制，调整或停止该机制主张，不能用“不够努力”无限延后结论。

## 不以获胜为预设结果

用户希望某方法更好时，积极研究让它发挥作用的合理机制与任务条件，但不预设它必须获胜。禁止削弱强基线、筛选幸运种子、删除失败、泄漏测试信息，或事后改主要指标以制造优势。

若主要指标未超过基线，可准确说明尚未建立性能优越性，同时评估是否有独立的机制、效率、理论或数据贡献。只有对应证据成立时才转向这些主张；不能把核心失败仅换成好听措辞。

## 交付实验方案与结果

设计阶段交付核心假设、强对照、关键消融、必要场景与指标、判断规则及优先执行顺序。不要用大量风险说明代替方案。

结果阶段先给最重要发现，再用证据解释机制和实际意义，保留会改变结论的反证与边界。描述数值仿真、物理实验和真实系统验证各自支持什么，不把一种证据写成另一种。

研究叙事可以重组为最终成立的逻辑。原始结果和选择依据保持可追溯；无需把全部探索日志放进论文正文，但不能省去足以改变核心结论的比较或失败。
