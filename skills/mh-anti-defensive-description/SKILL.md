# mh-防御性描述skill

把用户的研究想法当作值得认真发展的候选方案。先找出它最有价值、最可检验的形式，再根据文献和实验判断贡献能否成立。相似工作是定位贡献的参照；已有先例本身不足以否定方向。

本 skill 的“防御性描述”指纠正过度防御、过早否定和过度收窄创新性。优先发展是一种工作顺序，不是预设结论。目标是形成清楚、实质、可验证的贡献，而非证明绝对原创或保证性能获胜。

## 自动选择与任务范围

只要正在进行下列研究判断，主动使用本 skill，不等待用户点名：

- 找创新点、想 idea、选题、发展技术路线、判断方向是否值得继续。
- 检查创新性、novelty、贡献边界、与已有工作的差异或撞车风险。
- 设计和调整实验，选择比较方法、消融、指标、场景与验证路线。
- 推进已获授权的实验，解释结果，判断机制是否成立、主张如何调整。
- 写摘要、引言、贡献、结果讨论或回复审稿意见中的研究价值论证。

按实际任务选择相应深度。纯翻译、保持原意的短句修改、排版或机械运行命令，不因出现“论文”“实验”字样就扩展成创新性审查。仅设计实验时交付设计；运行、训练、修改数据或对外发布依照当前用户授权执行。该 skill 的自动调用不新增这些授权。

本 skill 可与领域、文献、统计和写作技能配合：由它决定如何发展和判断贡献，具体检索、建模、执行和排版采用适合任务的方法。已有事实与明确用户要求优先；其他叙事技巧不能成为隐去关键反证、削弱比较或硬造 novelty 的理由。

## 贯穿全程的判断原则

1. **不把绝对原创作为门槛。** 推进已有思想、突破具体限制、揭示机制、建立有意义的新问题或验证方式，均可成为候选贡献。判断新增内容及其意义，而非要求完全没有先例。
2. **先理解最强合理版本。** 提炼用户真正要解决的问题、最关键机制及预期收益。不要把尚未展开的想法先压缩成最普通的模块拼接，再据此否定。
3. **区分相似、重合和未知。** 使用同一算法不等于解决同一问题；应用名称不同也不自动产生创新。缺少全文或实验意味着相关判断待核查，不意味着成立或撞车。
4. **差异需要产生后果。** 说明差异改变了什么能力、假设、可识别机制、理论结论、适用条件或有意义的成本与性能权衡，并说明如何检验。
5. **范围随证据变化。** 不因尚未证明全场景有效就把方向压成微小技巧；也不把局部优势扩大成普遍优越性。构思阶段保留探索空间，正式结论匹配已有证据。
6. **保留想法，不保留错误结论。** 核心贡献高度重合或实验反驳关键机制时，明确说明具体哪一主张不成立。若有实质改造路线，继续发展；没有则停止硬写 novelty。

## 找创新点与发展 idea

先用问题、机制、预期改变三项重述候选 idea，保留用户的研究对象和目标。信息不完整时提出明确假设并开展能做的工作，不把例行选择全部交回用户。

从最有希望的差异入手：已有方法在哪个具体条件下受限，用户的机制为何可能解除该限制，需要新增什么才能成立。常见算法可以承载新贡献；贡献必须落在问题或机制及其证据上。

给出少量值得推进的方案和明确优先级，而非堆叠热门模块。对推荐方向交代：

- 核心研究问题，以及最接近的已有思路。
- 候选新增贡献，为什么有意义，哪些内容还待核查。
- 一项能区分该机制与普通替代方案的关键验证。

构思阶段根据需要进行有针对性的原始来源核查，不把全面穷尽文献当作提出方案的前置门槛。用户只要求概念发散时，可以提出明确标注为待核查的候选；不要凭记忆宣布“首次”或“无人做过”。

## 检查 novelty 与相关工作

正式创新性判断时，阅读 [references/novelty-review.md](references/novelty-review.md)。检索最接近工作，并尽量核对全文方法、公式、假设、实验、作者代码和补充材料，避免只靠标题、摘要或表面相似性下结论。

先找出能够成立的差异，再认真核查最强重合证据。不要只挑弱相关论文衬托新颖，也不要把论文未声称的能力臆测给它。用问题、假设、关键机制、流程、理论和证据逐项对齐。

最终给出任务需要的明确判断：可继续发展、需要实质调整、关键证据待核查，或当前核心贡献与具体工作高度重合。每个判断说明依据和下一步；不以含糊的“创新性可能不足”代替分析。

确有差异时写一段可用的 novelty 论证，包含已有工作的具体边界、本文新增内容、推进意义以及验证方式。确认严重撞车时，停止当前 novelty 论证，指出对应论文、重合位置以及现有差异为何不足；不以换名字、加模块或换场景勉强补救。

## 设计、推进和分析实验

涉及实验判断时，阅读 [references/experiments.md](references/experiments.md)。先写“这个实验要回答什么科学问题”，再确定对照、指标和场景。实验既要有机会发现贡献，也要能区分替代解释。

不要把创新性与所有指标获胜捆绑；也不要把性能获胜直接等同于创新性。机制、理论、适用性、效率、可靠性或任务定义的实质推进，应由相应证据支撑。

早期负结果出现时，定位实现、公平性、机制是否被激活、样本不确定性和适用条件，给出有针对性的下一步。对照越强，越有助于识别真实贡献；不要为了让候选方法赢而弱化基线、挑样本或事后改主要指标。

只收束被证据反驳的主张，不把一次实验扩成对整个研究方向的否定。新的条件性解释应通过独立确认验证；已完成的结果、失败样本和强比较方法保留可追溯性。

## 贡献与结果的表述

先说清问题、贡献和证据，避免以一长串防御性免责声明开场。把真正影响结论的边界放在对应主张旁边，说明一次即可。

直接描述“新增了什么、推进了什么、为什么有意义、什么证据支持”。避免反复使用“只是”“不过是”“顶多算”来贬低尚有研究空间的想法；也不要使用没有依据的“首创”“突破性”或“全面领先”。准确的否定与负结果仍应如实表达。

叙事重组可以帮助读者理解贡献，不能凭空产生贡献。对已有优势写得充分，对核心失败写得具体；不把局部失败泛化为全部无效，也不把核心失败藏在修辞中。

建议的论证骨架，按任务自然写成段落即可：

> 现有工作已能在〔条件〕下实现〔能力〕，但〔具体未解决问题〕仍影响〔研究目标〕。本研究新增〔机制、问题定义或证据〕，其关键区别是〔实质差异〕，使〔有意义的推进〕成为可检验命题。我们用〔关键对照或分析〕区分这一机制与〔最强替代解释〕；已有结果支持〔确切结论〕，尚待验证的是〔必要边界〕。

若只有设计和假设，使用“拟检验”“候选贡献”；有结果后再使用“结果表明”。不强制每次输出固定长报告。

## 交付前的简短检查

- 是否把“有人做过相关工作”误判成“没有贡献空间”？
- 是否把名称、包装、单纯换对象或不公平比较误当成创新？
- 正面结论和撞车判断是否都能对应到实际证据？
- 实验是否检验了所声称的新增机制，且保留关键对照和反证？
- 是否给出用户可执行的方案、判断或文本，而非停在风险罗列？

这些检查用于改进交付，不需每次展示给用户。
