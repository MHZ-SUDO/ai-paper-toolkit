# Word 模板与格式

模板用于专利工作稿，提供已确认的排版习惯和可编辑占位内容。它不是所有机构、地区或申报系统统一适用的法定格式；用户本次提供的正式模板或明确要求优先。最新版已接受文件也优先于较早的参考文件。

## 使用文件

- `../assets/patent-template.docx`：可直接复制后填写的空白工作模板。
- `../assets/format-profile.json`：页面、字体、段落、公式和图题规格。
- `../assets/boilerplate.json`：附图说明引言、具体实施方式开头及结尾的完整通用段落。
- `../scripts/create_template.py`：从资源重建模板，只依赖 Python 3.10+ 和 `python-docx`。

在 skill 根目录执行：

```bash
python scripts/create_template.py --output output/patent-draft.docx
```

输出文件存在时脚本拒绝覆盖；需要明确替换时再加 `--overwrite`。资源通过脚本所在位置查找，输出相对于调用者当前目录解析，不依赖开发者机器路径。脚本只生成模板，不生成虚构发明、权利要求事实、实验数据或附图。

所有 `【…】` 都是待填提示，必须依据当前项目资料替换或删除。未填写的模板不能作为已完成的专利正文交付。“完成人信息”仅供内部交底稿按需使用，不自动推断申请人或发明人。不要把同一具体名称、零件、技术参数或人物身份从旧项目带到新项目。

## 页面和角色样式

A4纵向，上下页边距25.4 mm、左右31.75 mm。正文黑色，中文宋体、西文 Times New Roman；所有正文相关样式关闭文档网格吸附。页脚为居中PAGE域，10磅。

| 角色 | 字号和字重 | 对齐与首行 | 行距 | 段前 / 段后 |
|---|---|---|---|---|
| 发明名称 | 14磅，加粗 | 居中，不缩进 | 最小24磅 | 0 / 10磅 |
| 分部标题 | 12磅，加粗 | 居中，不缩进 | 最小22磅 | 0 / 10磅 |
| 标准小节标题 | 12磅，加粗 | 左对齐，不缩进 | 最小20磅 | 6 / 4磅 |
| 正文及权利要求 | 12磅，常规 | 两端对齐，首行24磅 | 最小20磅 | 0 / 6磅 |
| 独立公式 | Cambria Math 12磅 | 居中，不缩进 | 最小22磅 | 3 / 3磅 |
| 图片段落 | 居中 | 不缩进 | 单倍，避免裁图 | 0 / 4磅 |
| 主图图题 | 12磅，常规 | 居中，不缩进 | 最小20磅 | 0 / 10磅 |
| 子图图题 | 12磅，常规 | 居中，不缩进 | 最小20磅 | 0 / 4磅 |

“最小行距”不是“固定行距”。大公式、上下标和图片不能为了压页数而改成过小的固定行距。用真实段落属性设置首行缩进，不用空格凑两字符；保留原生可编辑文字、公式和图题。

## 文档结构

依次为说明书摘要、摘要附图、权利要求书、说明书、说明书附图；各分部另起页，附图区按实际图量分页。“说明书附图”只写一次，不在每页或每张图片前重复。说明书保留技术领域、背景技术、发明内容、附图说明、具体实施方式五个标准小节。

正文默认不插入 `[0001]` 类段号。这与权利要求编号、图号、部件序号是四件不同的事，不能一并删除。权利要求和附图数量按实际方案设置，模板中的两条权利要求与图占位只是可扩展位置。

具体实施方式以工作过程串联，少设下级标题。先说明场景、初始状态，再说明触发条件、动作或计算、状态变化、输出和回程/反馈。必要安装、连接、约束关系放在解释动作、载荷或信号传递的段落中。不要重复列装配清单，也不能把必要结构关系全部删掉。

结构类突出构件配合与动作状态；控制类突出输入、计算、执行、反馈和触发条件；结构控制结合类明确控制输出如何改变结构状态、结构状态如何形成反馈。套话不决定技术路线，更不能替代这些具体内容。

## 完整通用段落

用户要求的“套话”包括：实施例可以在不冲突时组合、实施例的示例性质、术语“包括”等的解释、图示比例与示例数值、方位术语，以及最后的修改与等同替换说明。使用 `boilerplate.json` 中完整段落，放在具体实施方式开头和结尾，交付正文不必给它们另设标题。

根据实际内容选择段落：没有方位关系的方案可删除方位段；没有图或数值时调整对应表述。示例数值可以变化的说明须服从已披露的结构、步骤及公式条件，不能写成“任何参数、任意结构都可”。不要反复增加同义免责段，也不要用这些段落覆盖明确的技术关系。

## 图题、编号与附图

摘要附图采用能单独表达核心方案的清晰图，在此用户的工作稿中不加部件标号及“图N”题；说明书附图保留必要部件标记及对应图号。摘要采用哪张图由当前方案决定，不固定成“必须图2”。

主图图号放图下，用独立文字段落。子图分别插入为独立图像，`（a）`、`（b）`、`（c）`及其短说明放到各自图下，不能烘焙进图片。如果两图说明不同过程且需要独立引用，可分别编号为两个主图。图内只保留理解技术关系所需的短标注，长解释写正文。

“附图说明”列出各图含义和标记。“说明书附图”呈现图本身；这两部分不能混为重复内容而误删。插图使用足够清晰的原图和适当尺寸，不把图题、序号、引出线压入低分辨率截图。需编辑标注时交付原生PPT对象或相应可编辑来源。

## 原生公式

有必要时加入几何关系、力与力矩关系、运动关系或控制计算关系；不为显得复杂而堆公式。公式必须和真实结构/算法一致，定义每个符号、坐标方向、单位、符号正负及适用条件；对量纲、极限状态、符号和数值计算进行核查。

Word使用原生OMML公式，包含行内变量与下标；独立公式采用“专利公式”样式和 Cambria Math。不要把公式变成图片，也不要把 `T_1`、`alpha` 等源码当最终排版。模板只保留可删除的公式位置提示，没有预设任何发明公式或技术数值。

## 生成与检查

新文档先保留来源和版本，再按明确任务修改。模板脚本验证DOCX可读取、标准小节唯一、附图区标题唯一、没有外部链接和虚构嵌图；这些检查不证明最终分页和图形清晰。

完成真实内容后必须用可用的Word或兼容渲染器导出PDF/页图，逐页检查文字、公式、图题、图片、分页、页码和留白。只读导出优先；不保存渲染器对用户原件的隐式修改。记录真实工具和失败原因，不把ZIP/XML通过写成视觉检查通过。原件、渲染中间件和含私密技术的QA不要放入公开skill仓库。
