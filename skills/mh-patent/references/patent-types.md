# 类型与技术表达

先识别技术贡献落在哪里，再决定结构和控制各写多少。“控制结构”可能指控制系统架构，也可能指依赖特定机械结构的控制；“结构控制”也可能指结构与控制结合。结合用户原稿和图判断，不能仅按词序确定发明类型。

| 方案类型 | 必须说清的链条 | 合适的图与公式 | 常见失误 |
| --- | --- | --- | --- |
| 结构装置为主 | 部件 → 必要连接/相对位置 → 约束或传力 → 动作 → 作用 | 总体、关键局部、剖视/爆炸、状态图；必要尺寸关系或力/位移式 | 照产品说明列零件；加复杂控制掩盖结构贡献 |
| 控制方法为主 | 物理对象 → 测量/输入 → 状态计算 → 决策/控制量 → 执行器 → 反馈 | 控制架构、信号链、流程/状态机；必要模型与控制关系 | 只报算法名和优点；不知道输出控制哪个物理量 |
| 结构配合控制，结构为核心 | 结构提供的独特约束/动作 → 控制如何利用 → 实际作用 | 结构图为主，配必要驱动/感知位置和工作状态图 | 把普通闭环控制夸成另一主创新，冲淡结构主线 |
| 控制依赖特定结构，控制为核心 | 特定机构/布局 → 感知或可控关系 → 控制逻辑 → 技术效果 | 架构+执行单元布局+状态过程；必要分配、约束或切换公式 | 用抽象“控制模块”代替实际对象；结构与方程脱节 |
| 结构与控制共同构成机制 | 硬件关系与控制动作如何互相成立 → 时序/条件 → 闭环作用 | 联动状态图和信号/动作对应表，必要时分别提供结构和流程图 | 两份方案并排拼接，没有共同解决同一问题 |
| 工艺、制造、处理或测试方法 | 输入对象 → 操作次序 → 关键条件 → 中间状态 → 输出/检测 | 真正的工艺流程、设备配置或阶段示意 | 为迎合“不要流程条”而删掉本来必需的流程图 |
| 软件/数据处理的技术方案 | 输入的技术含义 → 处理关系 → 输出怎样作用于技术对象 | 数据/功能关系或处理流程，必要公式 | 用商业规则、名词清单或代码变量替代机制 |

这是一套写作分类，不替代申请类型、地区和保护客体的判断。用户另指定实用新型或其他申请类型时，保留有用的结构/图面习惯，重新核实适用范围，不直接套控制方法权利要求。

## 结构方案的连续实施段落

按真实顺序组织：“初始状态和必要连接 → 外部输入/载荷/驱动 → 部件相对运动 → 接触、变形或受力变化 → 约束/限位/复位 → 产生的作用”。只有图中或方案中存在的动作才写。

示意写法：某构件通过必要支承与另一构件形成允许的相对运动；输入发生时，先出现自由行程，达到接触条件后弹性件变形，继续运动时进入限位状态，输入解除后按真实设计恢复。这里各阶段、方向、零件号和条件均须替换为该项目已确认内容，不自动添加弹簧、传感器、复位能力或保险机构。

首次提到影响工作的位置/连接时用一句交代，后续不反复罗列。关键配合、自由度、承载路径或装配条件无法从图和文字确定时补清，常规螺钉等不承担核心作用的细节不必堆篇幅。

关键接口不能只写“连接”“串接”或“安装”。说明连接双方、固定或允许的相对运动、实际连接手段，以及方案中确实存在的密封/流道连续关系；可拆卸的固定连接不等于运动副。将外部接口的固定关系与内部轴承、铰接或滑动关系分开说明。先核对模型、图源或已确认方案，再写法兰、螺栓、焊接、密封垫等具体结构；没有依据时不自动补出。连接关系嵌入工作过程的初始段落，无需重新堆砌安装章节。

## 控制方案的连续实施段落

依次交代受控对象和目标量、可获得的测量、信号预处理或状态量、核心运算、控制输出及执行接口、反馈更新。涉及切换、饱和、失效保护或采样周期，按实际设计说明触发条件和动作，不凭习惯补模块。

用物理意义命名变量；同一符号全篇一致。公式应有输入、输出、单位/无量纲约定及边界条件。需要几何投影或力矩时核对坐标、方向、作用线和力臂。原理存在但数值未确定时用符号或待确认的合理参数化，不给虚构优化结果。

## 权利要求和说明书的关系

从同一关键机制组织必要技术特征，让结构关系或方法步骤相互连接。独立方案不机械收进每一个普通附件；有作用的可选细节再考虑从属层次。保留说明书对特征、术语和可选实施方式的支持。

修改具体实施方式时检查是否改变原权利要求基础；仅换字体/删图底说明不顺手扩写或缩写权利要求。用户要保护范围、授权前景或检索结论时，使用对应检索/法域资料，明确哪些是来源支持、哪些只是方案判断，不凭排版完成声称授权可行。
