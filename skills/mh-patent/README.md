# MH-Patent skill

按已确认的写作、附图和可编辑交付习惯处理专利。系统标识为 `mh-patent`，界面名称为 **MH-Patent skill**。

适用于结构装置、控制方法、结构配合控制、控制依赖结构、工艺及其他技术方案。能结合前文识别“这里不对”“这个图的PPT”等专利修改任务，不要求每次输入技能名称。

## 包含什么

- 最新意见优先、模板与事实分开、版本对应的工作规则。
- 以工作过程为主的具体实施方式，按需交代必要结构和公式。
- 通用专利说明段落与可编辑 Word 模板。
- 摘要附图、说明书标号、图外题注、过程虚线和完整主图的处理方法。
- 原生可编辑 PPT、模型依赖和整包交付的核验方法。
- DOCX/PPTX 只读检查脚本。

## 安装与自动调用

将整个 `mh-patent` 文件夹放到 `$CODEX_HOME/skills/`，未设置该变量时放到 `~/.codex/skills/`。刷新技能列表或在新会话中核对 **MH-Patent skill** 已出现。

`agents/openai.yaml` 中已设置 `allow_implicit_invocation: true`。也可显式使用 `$mh-patent`。自动发现允许助手按任务匹配，并不保证每个宿主都会自动读取新安装的文件；应实际确认技能已被发现。

希望在自己的全局指令中明确优先路由时，可以加入：

> 在编写、修改或检查专利及其附图、模型和可编辑资料包时，自动加载 `mh-patent`，无需用户点名；按当前任务读取必要参考资料。用户最新明确要求优先，普通非专利任务不触发。

## 使用示例

- “按这个模板把我的结构专利改一下，实施方式重点讲怎么工作。”
- “这是控制方法，先说清楚信号到执行器的过程，再写必要公式。”
- “这两张过程图分开，字母和图号放在图下面，给我能改标注的PPT。”
- “这是最新Word，把对应模型、图源和有用文件放一个文件夹。”

资源入口见 [SKILL.md](SKILL.md)。模板生成需要 `python-docx`；只读 OOXML 检查仅使用 Python 标准库。技能内的格式是用户偏好默认值，正式递交要求需按适用地区和当前规定核实。

仓库只包含通用规则、去标识模板和工具，不包含原始申请文件或发明模型。
